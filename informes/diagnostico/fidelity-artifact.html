Decoration preview pipeline · diagnosis

Why the preview doesn't look like the photo

Two reported problems — poor images from reference + space photo, and unstable colour detection — turn out to be the same problem seen from both ends: nothing measures what the photo looks like, and nothing measures whether the render matches it.

The findings that decide the plan

Eight facts

01

The reference photo never reaches an image model

With a space photo present, the LoRA is handed an empty image array and Gemini receives exactly two inputs: the venue and the LoRA render. The reference survives only as text.

Nothing forces the plan to use the photo's colours

Problem 1 · image fidelity

What breaks, named

F4

Two mirrored columns produce no image at all

Measured

resolveRelations skips the focal clause before assigning relations. When a bilateral pair is the only structure, that pair is the focal clause, so it never receives flanking. The caption then says both columns are standing apart on the left, the preflight demands the mirror phrase, and the request throws.

Scenario A (two columns alone) fails. Scenario B (arch + two columns) passes. Zero of the 24 frozen plans have shape A — the suite cannot regress on a shape it does not contain.

lora-caption-compiler.ts:750 · :1029 · :1040 · lora-prompt-preflight.ts:185 · route.ts:1148
F5

The 36-inch topper is quoted, charged, and dropped from the prompt

Measured

Of 27 product concepts, only 2 allow R-36 and 4 allow R-24. A size outside allowed_codes is omitted with nothing but a diagnostic line. That is the mechanism behind "no dominant topper" and behind the LoRA evaluation's 0/6 on diameter — a data gap, not a model failure.

Corroborated in production: 171 of 971 audit rows are SIN_COBERTURA carrying a balloon size code. The largest error family in the log.

product-vocabulary-data.ts · route.ts:1086 · plan_audit_log
F6

The caption is written in a register the model never saw

Measured

Across the 345 training captions: 345/345 close by describing a real background, 245/345 name props, and 0/345 contain an imperative prohibition. The runtime appends 290 characters of exactly that.

A correction to the earlier diagnosis: the compiled caption for the control design is only 289 characters, well inside the 460 available. The binding constraint is not length — it is register. Freeing characters alone will not help.

Problem 2 · chromatic distance

One axis where it needs three

The substitution table stores a single hue angle per catalog colour. Lightness and saturation are absent, so colours that differ only on those axes score as nearly the same colour. Every distance below was measured by running the function.

Grey compounds it: there is no gris in the 26-colour catalog palette at all, so it is filtered out of the catalog search before substitution even runs — and the LoRA's own corpus does know the word grey. The table is correctly shared with Python through the contract, so both runtimes are equally wrong and one fix corrects both.

Measured

Six phases · ordered by evidence per unit of cost

The plan

Each phase is independently shippable and reversible, and states its acceptance criterion before the work starts. Phases 0–2 need no provider credit.

0

Make the system measurable

No fal1 day · US$0

Nothing here improves an image. It is the precondition for judging everything after it: today a prompt change cannot be attributed, because the seed moves underneath it.

  • Pin the seed on the evaluation path; keep the random draw for customers.
  • Declare the active slot and its evaluation status in the response and the UI — modeStatus already returns testing_rejected and nothing shows it.
  • Restore the v004 caption corpus, absent from the checkout, so the affinity harness can run against the model production actually serves.
  • Call the deterministic background-similarity function on the (venue, generated) pair instead of trusting the model's invented number.
  • Record input-image hashes, seed, slot, caption hash, preflight result, dropped sizes and QA verdict.

AcceptanceTwo consecutive generations of the same plan at the same explicit seed return byte-identical stage-1 images; every row names its slot, seed and a non-null QA verdict.

1

Stop failing closed, stop losing data

No fal2–3 days · US$0

Pure defect repair. No prompt rewriting, no architecture change. Every item has a deterministic test that fails today.

  • Give a bilateral clause its mirror relation even when it is the focal clause; key the renderer off clause.bilateral rather than the word flanking.
  • Add the three fixtures that would have caught it — including one asymmetric pair that must not be mirrored.
  • Surface dropped sizes as a named condition, then fill allowed_codes against the live snapshot. Treat the 171 SIN_COBERTURA rows as one population.
  • Re-admit reference scenery when a venue exists — it already has its own gate and never touches quoting or plan_hash.
  • Reconcile the UI comment with what the server does. Do not leave both.

AcceptanceA two-column plan generates an image; a 36-inch topper either reaches the caption or reports why it cannot, never silently omitted; the full TypeScript and pytest gates green.

2

Make colour measured instead of guessed

No fal1 week · ~US$5

The whole of Problem 2, and none of it waits on provider credit.

  • Measure dominance from the pixels. The analyser may keep proposing names; the ranking and the share must come from measurement. Every other colour finding is downstream of not having this number.
  • Constrain the analyser's colour output at the schema level instead of folding free text afterwards, and take the palette from measured shares rather than the second, independently unstable palette field.
  • Stop breaking neutral-family ties alphabetically — gris must resolve to plateado, not negro.
  • Extend the distance table to hue + lightness + saturation, through the contract, in the one direction allowed: Zod → export → generate models → regenerate golden vectors.
  • Decide what grey is — sell it, substitute it deliberately, or declare it unavailable. Today it does a fourth thing: vanishes, or turns black.
  • Let the audit pass carry observed_colors through the merge, so the second vision pass can finally correct the field that varies most.
  • Decide what the photo palette is allowed to do. Ranking context, soft boost with a recorded penalty, or hard filter with an explicit relaxation rung. A product decision — but the current state is not a decision, it is three gaps stacked.
  • Compare declared participacion against the measured reference share, as a warning first. Promote to a constraint only if the data earns it.

AcceptanceThe same photo yields the same measured palette across five runs — today, four different palettes out of five on both test photos. The four near-identical colour pairs separate. A colour that cannot be honoured is reported before generation, not after.

3

Align the caption with the model's own dialect

2 days · ~US$5

Partly pre-measured: the run above already identified the change on the approved slot. What remains is reaching the bar over 10 plans instead of one design and two seeds.

  • Replace the 290-character prohibition block with the corpus's closing clause — measured at 7 vs 4 on isolation. Not shortened, not deleted: replaced.
  • Establish which dialect v004 speaks for the remaining vocabulary questions — the corpus measurements so far are on v007, which is rejected.
  • Stop emptying the visual context, and move the asymmetry patch into the compiler as mixed organically rather than graded — the phrase the corpus uses 218 times.
  • Decide the finish vocabulary from that measurement, not from v007. Do not guess.

AcceptanceOver 10 frozen plans, judged pairwise in a single call per pair, the new caption wins on photorealism and size variation in ≥7 of 10, with no preflight or colour-coherence regression. Seeds pinned, so the caption is the only variable.

4

Let the reference arrive as pixels

3–5 days · ~US$15

The real ceiling. Two options — measure before choosing.

  • A. The LoRA edits the space photo directly through /edit. One call instead of two; removes the compositing and contact-shadow defect entirely; halves the cost per preview. The helpers are already written and tested. The risk is real: /edit has never been measured with this LoRA.
  • B. Keep both stages and give each what it lacks — the reference as composition_reference in stage 1 and palette_reference in stage 2. Both roles already exist and are simply discarded.

AcceptanceWins on photorealism and usability in ≥7 of 10 and the visual QA does not worsen conformance to the approved plan. If quality rises and plan fidelity falls, do not promote it — the proposal is what the customer is charged for.

5

Retrain, only if the evaluation still fails

2–3 weeks · ~US$40

Last, because until Phases 3 and 4 land nobody knows how much of the problem was the caption. The v007 rejection is specific: colour 6/6 pass, finish 0/6, diameter 0/6 — both failures look like dataset properties.

  • Count how many dataset images are genuinely matte before retraining anything. If every order photo carries flash highlight, the model never saw the contrast.
  • Diameter needs captions that state the size relation and sampling that guarantees contrast within one image — and Phase 1 must land first, or the retrained capability stays unreachable.
  • Re-label 40 images with verified finish and diameter, measure the imbalance, then choose re-captioning over re-collection.

AcceptanceThe existing protocol, unchanged to make it pass: 6 seeds, minimums 5/6 colour, 5/6 finish, 4/6 diameter, promoted through the registry rather than the testing override.

Measured dead ends and traps

What not to do

✕

Don't raise guidance scale or LoRA scale. Already measured flat at 8.0–8.5 across 2.5–5.0 and 0.6–1.0. The creativity levels neither explain nor fix this.

✕

Don't add another prohibition to the caption. Each one consumes budget and none exists in the training register — 0 of 345 captions contain an imperative. The three current patches are a symptom.

✕

Don't touch the finish vocabulary before restoring the v004 corpus. v007 says high-shine Reflex; the active model may well speak chrome, which is what the runtime already emits. Changing it now could make things worse.

✕

Don't judge quality on training_2. It is rejected and production cannot serve it.

✕

Don't turn the visual QA off to make images pass. It was the only component that saw the problem, and it was right.

✕

Don't compare judge scores across runs. The rubric judge recalibrates to the set it is shown — the same variant scored 7 in one batch and 8.5 in another. Scores order variants within one call; they are not an absolute metric.
