# Plan 08 — E2E, build, documentación y rollback

## Objetivo

Cerrar la regeneración solo con evidencia end-to-end, fallback sin key y un procedimiento operativo reversible.

## Tareas

### 1. Ejecutar E2E determinista y opcional

- **name:** `e2e-rag-gate`
- **files:** `scripts/eval-e2e-rag-v2.ts`
- **action:** Probar health, búsqueda exact/semantic, filtros color/forma/tamaño/precio/stock, SKU ambiguo/inexistente, whitelist, selección, subtotal y cotización desde DB; repetir mediante una opción `--no-key` y, si existe, con Gemini/vector.
- **verify:** `npx tsx scripts/eval-e2e-rag-v2.ts --no-key` y `npx tsx scripts/eval-e2e-rag-v2.ts --with-gemini` (cuando haya key) demuestran 0 IDs/precios inventados, 0 variantes fuera de whitelist, 100 % precio exacto de DB, parser 3/3; `SKIPPED_OPTIONAL` solo para vector/Gemini sin key; E2E p95 <=1,15× baseline.
- **done:** Reporte exit code no-cero ante cualquier invariant violation.

### 2. Escribir runbook y rollback

- **name:** `operations-runbook`
- **files:** `docs/operations/rag-regeneration-v2.md`, `docs/operations/rag-rollback-v2.md`
- **action:** Documentar compose, env, migraciones, snapshot/hash, staging→publish, embeddings, flags, no-key path, stale/partial fetch, observabilidad, promoción, rollback de schema/datos/índices y retención sin PII.
- **verify:** Una persona puede repetir bootstrap y rollback solo con los comandos documentados; no hay secretos ni órdenes crudas en ejemplos.
- **done:** Runbook incluye umbrales de bloqueo y recuperación.

### 3. Cerrar release y estado

- **name:** `release-handoff`
- **files:** `release-manifest.json`, `.planning/STATE.md`
- **action:** Añadir un bloque RAG versionado a `release-manifest.json` sin borrar ni sobrescribir los metadatos LoRA existentes; registrar URLs, hashes, conteos, versión de schema/taxonomía, modelo/dimensión opcional, métricas, comandos, flags y resultado de cada gate; actualizar STATE solo con evidencia.
- **verify:** Manifest no contiene API keys/customer IDs; todos los gates de `PROJECT.md` tienen PASS o razón `SKIPPED_OPTIONAL/BLOCKED` explícita.
- **done:** No quedan P0 abiertos y el release es reversible; si un P0 persiste, estado `BLOCKED`.

## Gate del plan

`npm run build`, health, import idempotente, benchmark fijo y E2E pasan; documentación de rollback lista; la capacidad sin Gemini funciona y las opcionales están etiquetadas.
