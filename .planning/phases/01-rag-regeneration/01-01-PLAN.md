# Plan 01 — Runtime, Docker y build base

## Objetivo

Dejar un runtime local reproducible para continuar la regeneración, sin asumir que Docker ya contiene imágenes, volúmenes o credenciales. La configuración debe servir también para probar el fallback sin Gemini.

## Contexto y límites

El contexto auditado tenía Docker Engine disponible pero 0 contenedores e imágenes. `AGENTS.md` exige leer la guía instalada de Next.js 16 antes de modificar código de Next/build. No crear secretos, no tocar producción y no borrar volúmenes existentes.

## Tareas

### 1. Parametrizar compose y entorno

- **name:** `runtime-env`
- **files:** `docker-compose.yml`, `.env.example`
- **action:** Parametrizar usuario, password, base, puerto y `DATABASE_URL` con variables de entorno; mantener pgvector/unaccent; evitar credenciales hardcodeadas y exposición amplia por defecto. Documentar `GEMINI_API_KEY` como opcional y `GEMINI_EMBEDDING_DIMENSIONS`/flags como variables explícitas.
- **verify:** `docker compose --env-file .env.example config` no muestra claves reales ni errores; el servicio declara healthcheck y volumen nombrado.
- **done:** Configuración válida, sin cambios destructivos y con instrucciones de arranque/paro reproducibles.

### 2. Crear health check y comandos de runtime

- **name:** `stack-health`
- **files:** `scripts/stack-check.ts`, `package.json`
- **action:** Añadir un script de health que compruebe conexión SQL, extensiones `vector` y `unaccent`, dimensión esperada y presencia/ausencia de Gemini como `READY` o `SKIPPED_OPTIONAL`; agregar comando npm sin cargar secretos desde el código.
- **verify:** Con DB caída `npm run rag:stack-check` devuelve estado no saludable; con DB arriba diferencia `GEMINI_API_KEY` ausente de un error de PostgreSQL; no importa módulos que fallen por `server-only` fuera de `react-server`.
- **done:** `npm run rag:stack-check` existe y su salida es accionable.

### 3. Establecer build gate

- **name:** `next-build-baseline`
- **files:** `package.json`, `docker-compose.yml`, `src/components/TarjetaCotizacion.tsx`
- **action:** Ejecutar la guía Next.js pertinente desde `node_modules/next/dist/docs/`, verificar TypeScript/ESLint/build y corregir la incompatibilidad reproducida en `TarjetaCotizacion`: `src/app/page.tsx` le pasa `editable` y `onAplicar`, pero el componente actualmente solo declara `cotizacion`. Mantener la corrección limitada a props/tipos/comportamiento de ese componente y a configuración/runtime imprescindible para compilar sin DB/Gemini.
- **verify:** Leer la guía aplicable bajo `node_modules/next/dist/docs/` antes de editar; reproducir el error de props, corregirlo en `src/components/TarjetaCotizacion.tsx` y ejecutar `npm run build` en un entorno sin `DATABASE_URL` ni `GEMINI_API_KEY`; cualquier cambio queda anotado en el reporte.
- **done:** Build base verde y la discrepancia de props de `TarjetaCotizacion` resuelta antes de implementar contratos o ingesta.

## Gate del plan

`docker compose config`, `npm run rag:stack-check` y `npm run build` pasan; la rama opcional de Gemini queda identificada como `SKIPPED_OPTIONAL` cuando no hay key.
